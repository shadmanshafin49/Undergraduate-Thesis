# OBJ-15 two-factor decomposition -- dataset vs partition

Generated by `experiments/sweeps_cross_condition.py`. Every number is read from `results/*.json`; nothing here is estimated, and no significance is claimed -- each condition is a single run, so these are differences between point estimates, not tests.

**Why the two effect columns exist.** OBJ-15 moved dataset and partition together (ULB had only ever run stratified; BankSim ran entity-disjoint), so none of its divergences could be attributed to either alone. Splitting the change into `ULB/strat -> BankSim/strat` (dataset) and `BankSim/strat -> BankSim/entity-disjoint` (partition) is the whole point of the control run.

**A property that makes this cleaner than the federated ablation:** none of the four sweeps passes `groups=` to `ADTCN.fit()`, and `fit(groups=None)` builds global windows, so *both* BankSim partitions window identically. The partition column moves the partition and nothing else. (The corollary is that the entity-disjoint sweeps measure orgs holding disjoint customers but *global* windows -- do not describe them as using customer-linked sequences.)

- **ULB / stratified** -- 4/4 sweeps on disk
- **BankSim / stratified** -- 4/4 sweeps on disk

**The artefact that blocks reading any of this as "FedAvg wins":** how many attacked FedAvg runs score *above* their own no-attack reference by more than 0.5 pp. An attack cannot improve a model, so a non-zero count means balanced accuracy is rewarding noise-induced positive bias and the Krum-FedAvg gap above is not a clean utility comparison.

## Task B1 -- private incentive channels (**Incentivized**, privacy<->incentive)

`private_incentive_sweep` -- conditions on disk: ULB / stratified, BankSim / stratified, BankSim / entity-disjoint

**eps\* = the largest swept budget at which rewards are STILL mis-ranked (higher is worse). The claim under test is the ordering -- output channel beats weight channel -- not the constants.**

| Quantity (metric named) | ULB / strat | BankSim / strat | BankSim / entity-disj | dataset effect | partition effect |

> A factor above is a LOWER BOUND wherever the next table says RIGHT-CENSORED, and it is not quotable at all wherever the fragility table after that flags either end. Both checks have to pass.

**Censoring check -- is the weight channel still inverting at the top of the grid?** Where it is, eps\* is right-censored and the factor above is a LOWER BOUND, not a measurement (this is what forced ~60x -> >=60x).

| Condition | max eps swept | weight inversions there | eps\* status |
|---|---|---|---|
| ULB / stratified | 30000 | 0/100 | measured |
| BankSim / stratified | 30000 | 0/100 | measured |
| BankSim / entity-disjoint | 30000 | 0/100 | measured |

**Fragility -- how many draws decide each eps\*?** eps\* is the threshold `inversion rate > 0`, so ONE inverted draw can set it. A rate of 0.01 reads like a small number and at 100 repeats it is a single coin-flip. Both ends of every ratio are checked, with exact (Clopper-Pearson) 95 % intervals.

| Condition | channel | eps\* | draws deciding it | exact 95 % CI | verdict |
|---|---|---|---|---|---|
| ULB / stratified | weight | 3000 | 1/100 | 0.0003-0.0545 | **FRAGILE -- 1 draw** |
| ULB / stratified | output | 50 | 1/100 | 0.0003-0.0545 | **FRAGILE -- 1 draw** |
| BankSim / stratified | weight | 3000 | 1/100 | 0.0003-0.0545 | **FRAGILE -- 1 draw** |
| BankSim / stratified | output | 100 | 1/100 | 0.0003-0.0545 | **FRAGILE -- 1 draw** |
| BankSim / entity-disjoint | weight | 10000 | 13/100 | 0.0711-0.2120 | measured |
| BankSim / entity-disjoint | output | 300 | 11/100 | 0.0562-0.1883 | measured |

> **eps\* only ever moves UP, and that is a property of the estimator, not of the mechanism.** Draws are seeded `np.random.seed(3000 + rep)`, so a larger `--repeats` strictly CONTAINS the draws of a smaller one: an eps that inverted once at 100 repeats still inverts at 1000, and an eps that showed 0/100 may start inverting. Extending the grid works the same way -- a new budget can only add inversions. So `max{eps : rate > 0}` is non-decreasing in both the repeat count and the grid extent, and a 'de-censoring' means the added budgets happened to show zero, not that a population quantity was located. Read eps\* as *the largest budget at which an inversion was CAUGHT*, and quote the rate with its interval alongside it.

## How to read the two effect columns

- A quantity that moves in the **dataset** column and not the **partition** column is a property of BankSim, and any claim about federation structure built on it in OBJ-15 must be withdrawn.
- A quantity that moves in the **partition** column is a property of entity-disjointness, and it generalises past this dataset only as far as the mechanism does -- state the mechanism, not just the sign.
- A quantity that moves in **both** is not decomposable from three runs. Say so; do not attribute it.
- A quantity that moves in **neither** replicates, and that is a result worth stating plainly (rule 3 cuts both ways).
